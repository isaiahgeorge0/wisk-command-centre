# Winston — Integration Catalog

Last updated: August 2026. Single reference point for every place Winston shows up in the product, plus the shared infrastructure it's built on. Read this before building any new Winston feature.

## Core AI infrastructure

- `ai_conversations` / `ai_conversation_messages` (migration 032) — full conversation history. Scopes are isolated and never merged:
  - `project_id` — optional project-linked general chats
  - `note_id` (migration 069, unique per user/note) — record-level Notes brainstorm (predates generalized record keys)
  - `scope_key` (migration 072, unique per user where set) — page-level and record-level threads. Page keys: `global`, `notes`, `leads`, `properties`, `projects`, `tasks`, `goals`, `ideas`, `calendar`, `content-calendar`. New record types use composite keys (`lead:<uuid>`, `project:<uuid>`) — do **not** add another dedicated column per entity. `global` is isolated from unscoped Winston Chat.
  - Unscoped (all of the above null) — general Winston Chat only. Chat list excludes `note_id` and `scope_key` rows so surfaces cannot collide.
- Message durability: `POST /api/winston/chat` writes the user message to `ai_conversation_messages` **before** the Anthropic call, and the assistant reply **after** the stream completes on the server. SSE `enqueue` failures (client gone) do not abort persistence. Reopen rehydrates via `getOrCreateNoteConversation` / `getOrCreateScopedConversation` + message fetch — not a blank chat.
- `ai_context_cache`, `ai_usage_log` — context caching and per-feature token usage tracking. `ai_context_cache` is also used as a 15-minute nested-key cache for email action-items (`email_action_items` key inside the jsonb), not just business context.
- Gating: `ai_access` (boolean on `user_preferences`, admin-overridable) plus an active `user_subscriptions` row. A user can hold **multiple simultaneous subscription rows** (one per package) — never assume one row per user when checking entitlement; this caused a real bug (see Morning Briefing below).
- **Shared proposal infra** (`src/lib/winston/proposal.ts`, `commit-proposal.ts`, `src/components/winston/`) — the pattern for any feature where Winston suggests a *set* of structured items for review before creation. `WinstonProposal` / `WinstonProposalItem`, five `entityType`s (`project`, `task`, `calendar_event`, `content_post`, `idea`), each item carries a `reasoning` string (never blank — explainability isn't optional). `WinstonProposalReview` component handles checkbox/edit/add/remove/commit; `commitWinstonProposal` dispatches to the **existing** per-entity creation actions (no parallel creation logic), resolves new-project → task `projectRef`s, supports partial success with per-item errors, and threads an optional source context through (e.g. sets `projects.source_note_id` when the source was a note). Nothing is created until explicit commit — matches "human approval before consequential actions" the same way every other Winston write does. Sidebar conversations do **not** lock `allowedEntityTypes` to the current section — a mix is allowed when the transcript warrants it. Section context is bias in the system prompt, not a hard block. Creation only (no “update this existing record” diffs yet).
- **Reliability/cost infrastructure added this pass:**
  - Timeout constants (`ANTHROPIC_TIMEOUT_MS` 30s, `ANTHROPIC_VALUATION_TIMEOUT_MS` 90s, `ANTHROPIC_STREAM_TIMEOUT_MS` 60s) — every Anthropic call site now has a deadline; previously none did.
  - `cachedSystemPrompt` / `cachedSystemParts` (`src/lib/ai/anthropic.ts`) — Anthropic prompt caching (`cache_control`, 1h TTL) applied across chat, digest, morning briefing, property insights, call notes, action items, portal triage, lead draft-email, pipeline health, and inbox email draft.
  - `formatBusinessContext()` — digest-style sliced context, replaced the raw `JSON.stringify(context)` dump previously used in Winston Chat.
  - `EMAIL_BASE_URL` / `emailUrl()` — dedicated production-locked URL source for anything that goes into a real outbound email (separate from `NEXT_PUBLIC_SITE_URL`, which can legitimately be localhost in normal dev). `assertEmailHtmlSafe()` throws if `localhost` reaches a real Resend call. Built after a real incident — see Morning Briefing.

## Three-tier sidebar (layout-level)

One shared `WinstonSidebar` (Leads-panel visual pattern, Winston purple via `--wisk-section-winston`) mounted in `AppShell`. `resolveWinstonContext()` maps the trigger that opened it to `scope_key` / `note_id` and the system prompt. Entry chrome is `WinstonEntryButton` / `WinstonSectionEntry` / `WinstonFab` — never the local section colour.

1. **Global icon** (bottom-right FAB, replaces quick-add FAB) — `scope_key: 'global'`, zero page context, same everywhere. Default tab is structured **Quick add**: compact in-sidebar forms for task, calendar event, note, lead, project, idea, goal, and content post, each calling that entity’s existing create action. Chat is the other tab. Free users get a real Haiku conversation (`claude-haiku-4-5-20251001`), capped at 3 exchanges/day via `ai_usage_log` `feature=chat` (`WINSTON_FREE_DAILY_MESSAGE_CAP`). After the cap: upgrade prompt, not a dead end. Proposals are permitted on free within that cap.
2. **Section** — “Brainstorm with Winston” on each section page (`notes`, `leads`, `properties`, `projects`, `tasks`, `goals`, `ideas`, `calendar`, `content-calendar`). Knows the section, not a record. Paid (`ai_access`); free users see an upgrade teaser.
3. **Record** — icon + “Winston” only, inside a specific record. Notes still use `note_id` and preload that note’s content; “Insert into note” stays. New record types should use composite `scope_key`s. Paid; free users see the teaser.

Leads keeps its existing tools panel (call notes / drafts / Pipeline Health) in addition to section brainstorm; that chrome is Winston purple too.

## Every current surface

1. **Winston Digest page** (`/ai-digest`) — weekly summary cards. `claude-sonnet-4-6`. Batch generation now correctly filters to entitled users (`ai`/`ai_pro`/`max` + admin override) — previously ran for every user regardless of access, a real cost leak that's now fixed.
2. **Winston Chat** (`/ai-digest/chat`) — conversational Q&A. `claude-sonnet-4-6` reply + `claude-haiku-4-5-20251001` title. Now **streams** (SSE: `meta` → `delta*` → `done` → optional `title`); title generation runs after `done` so it no longer blocks first tokens. Context uses `formatBusinessContext()`, not a raw object dump.
3. **Overview: Winston suggests strip** — suggestion pills. `src/components/overview/winston-suggests-section.tsx`.
4. **Overview: Morning Briefing** — see dedicated section below, changed substantially this pass.
5. **Overview: While You Were Away** — cached catch-up summary, `ai_pro`/`max` only (unchanged, intentionally narrower than digest). Cron now tracks a `failed` count like the others.
6. **Leads: Winston side panel** — hosts call-notes processor, email drafting, and Pipeline Health (now live).
7. **Leads: Call notes processor** — `claude-haiku-4-5-20251001` (downgraded from Sonnet this pass — schema-constrained extraction, same class of work as lead draft-email).
8. **Leads: Winston email drafts** — `claude-haiku-4-5-20251001`, unchanged.
9. **Leads: Pipeline Health** — **now fully built**, was a stub as of the last sync. `claude-sonnet-4-6` (upgraded from an initial Haiku pass — this is advisor-style interpretation, same family as digest/briefing, not simple extraction). Computes stalled leads, time-in-stage, conversion trends, and value-at-risk server-side; Winston only writes qualitative reasoning. `value`/`valueType` on every flagged lead are sourced directly from the `leads` row and rendered by the UI — **never generated by Winston's prose** — after a real bug where a £15 lead displayed as "£15k" because the model was restating the figure itself. Standing rule from that bug: no Winston-generated text should ever contain an exact number the model computed itself; numbers are computed in code and either not repeated in prose or passed in pre-formatted with an explicit "state this exact figure" instruction.
10. **Leads: automated follow-up drafting** — stalled leads flagged by Pipeline Health get a "Draft follow-up" action that seeds the existing `WinstonEmailDraftCard` with that lead plus Pipeline Health's `issue`/`suggestedAction` as extra context, auto-calling `/api/winston/draft-email`. Same review/edit/send path as manual drafts — nothing sends automatically. Leads without an email show a prompt to add one instead of a broken action. Manual lead edits clear the passed-through Pipeline Health context so a later draft doesn't reuse stale reasoning.
11. **Email inbox: Winston draft panel** — `claude-haiku-4-5-20251001` (downgraded from Sonnet — was inconsistent with lead draft-email doing the same class of work on Haiku already). Email body truncated at 8k chars before drafting.
12. **Email inbox: Winston Picks** — curates top-priority unread emails, pre-generates drafts on a schedule, cached per UK date window.
13. **Email inbox: action items** — `claude-sonnet-4-6`. Now has client-side fingerprint+400ms-debounce+abort dedup and a 15-minute server cache (`ai_context_cache`, nested key), so it no longer fires a fresh Sonnet call on every inbox reload/provider change/search.
14. **Properties: Winston page** (`/properties/winston`) — portfolio insight cards, `claude-sonnet-4-6`. DB selects narrowed (payments/tickets limited to 24 months) and prompt lists capped (properties 25, tenants 20, maintenance 15, reliability 20) — previously unbounded.
15. **Tenant portal: maintenance triage** — `claude-haiku-4-5-20251001`, unchanged.
16. **Settings: Winston controls** — usage display, email picks toggle.
17. **Admin: Winston controls** — per-user access toggle, manual digest generation.
18. **Notes: record-level Winston** — “Winston” in the note editor opens the shared sidebar scoped to that note (`ai_conversations.note_id`). Context is the note's title + plain text (`extractPlainTextFromNoteContent`) — not broader business context. Each reply has “Insert into note” (cursor insert or append, immediate save) — still one explicit click, never automatic. Section-level “Brainstorm with Winston” on the Notes page is a separate `scope_key: 'notes'` thread.
19. **Notes: Find projects & tasks** — distinct entry point from brainstorming (one-shot generation, not a conversation). `claude-sonnet-4-6`. Reads note text plus a lightweight list of the user's existing active projects, so it can attach a proposed task to something that already exists instead of always inventing a new project. Produces a `WinstonProposal` (`project`/`task` items only) reviewed via the shared component. Commit sets `projects.source_note_id`. Returns a clear "nothing actionable" state rather than forcing output when a note has nothing worth converting.
20. **Section brainstorms** — “Brainstorm with Winston” on Calendar, Content, Notes, Leads, Properties, Projects, Tasks, Goals, and Ideas. Each has its own `scope_key`. Per-message “Create this” → mixed-type `WinstonProposal` (conversation decides types; section is prompt bias only). Threads never share message history across scopes.
21. **Global Winston FAB** — sitewide Sparkles icon. Quick-add tab first; chat tab is `scope_key: 'global'`. Free: real Haiku, 3 messages/day. Paid: Sonnet, existing monthly/short-term limits.

## Known dead end (fixed, keep for institutional memory)

**Pipeline Health's spinner bug** (fixed): not an Anthropic timeout — a client `useEffect` had `loading` in its own dependency array, so setting `loading` re-triggered the effect, which saw itself "already in progress" and bailed before the original fetch's cleanup could clear the flag. Fixed by keying the effect on `[open, result]` only and forcing `loading` false on cleanup. Worth remembering as a pattern to avoid elsewhere.

## Morning Briefing — substantially reworked this pass

- **Standard/free feature now**, not `ai_pro`/`max`-gated. Eligibility check no longer filters `user_subscriptions` at all; every user gets a briefing, tiered by whether they have `ai_access` (any active `ai`/`ai_pro`/`max` subscription, or admin override).
  - **Paid tier:** unchanged — `claude-sonnet-4-6`, full `{headline, summary, focuses, encouragement}` shape, `content.tier: "paid"`.
  - **Free tier:** `claude-haiku-4-5-20251001`, `max_tokens: 180`, a single `insight` field, `content.tier: "free"`. Card and modal both show the simpler experience with a light upsell line ("One insight a day, free. WISK AI unlocks Winston's full potential — all day, not just the morning."); email CTA: "This was one insight. WISK AI gets you all of them." Upsell copy is a first draft, not final brand copy.
- **Two real bugs found and fixed in this feature:**
  1. **Stale time-window gate** — leftover logic checked whether the current time fell inside a narrow window (07:25–07:35 / 07:30–07:40), built for a `*/5` Vercel Pro cron. On Hobby, the cron only ever fires at exactly `:00`, so the window never matched and every user was silently skipped, every day, despite a clean 200 response — zero rows were ever created before this fix. Now gated behind `MORNING_BRIEFING_FREQUENT_CRON` (default off); on Hobby, the cron firing *is* the trigger. Structured run summaries (`eligible`/`generated`/`skipped`/`failed`) are now logged plainly in Vercel logs, not just buried in the HTTP response — `away-sync` got the same `failed`-tracking parity fix.
  2. **Localhost link incident** — a manual verification run (triggered from local dev, against the real production DB and live Resend key) sent real emails to real users with CTA/logo links built from `NEXT_PUBLIC_SITE_URL=http://localhost:3001`. Confirmed the stored `content` itself was clean (relative `href`s), so the blast radius was the two live emails, not corrupted data — `sanitizeBriefingContent()` was added on read/store anyway as defense-in-depth. Root fix: `EMAIL_BASE_URL`/`emailUrl()` (see infra section above), plus generate/send now require `VERCEL_ENV=production` (local calls get 403 unless `ALLOW_LOCAL_MORNING_BRIEFING_CRON=true` is deliberately set).
- Send now picks any unsent briefing from the last 36h, no package filter (matches the open-to-everyone generation change).

## Notification type

`notifications.type` check constraint extended (migration 071) to include `'awaiting_date'` — a one-shot reminder created when a Winston proposal commits an undated `idea` or content post, explicitly excluded from whatever regeneration sweep (`generateNotifications`) exists so it isn't silently wiped. Ideas and the Content Calendar board both have an "Awaiting a date" filter/badge as the persistent (non-nagging) surface for these.
